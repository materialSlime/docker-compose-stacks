docker-compose-stacks · a beginner's guide

Make is a file of named shortcuts

You write long commands once in a file called Makefile and give each one a short name. After that you type make up and Make runs the whole list for you, in the right order. It's already installed on your server at /usr/bin/make.

Why bother

Seven folders, one command

Today: start everything by hand

cd ~/docker-compose-stacks/traefik    && docker compose up -d
cd ~/docker-compose-stacks/bind       && docker compose up -d
cd ~/docker-compose-stacks/core       && docker compose up -d
cd ~/docker-compose-stacks/immich-app && docker compose up -d
cd ~/docker-compose-stacks/arr        && docker compose up -d
cd ~/docker-compose-stacks/monitoring && docker compose up -d
cd ~/docker-compose-stacks/portainer  && docker compose up -d

You also have to remember to create the networks first and to start Traefik before the rest.

With a Makefile

make up

Make creates any missing networks, then starts each stack in order. If one stack fails, it stops there so the error is easy to see.

Anatomy

Each shortcut is called a rule

A rule has a name (the target), an optional list of other targets to run first (dependencies), and the shell commands to run (the recipe). This is the up rule from your Makefile:

up: network
⇥TAB@for d in $(s); do (cd $$d && docker compose up -d) || exit 1; done
upThe target, which is the name you type: make up.
: networkDependencies. Make runs the network rule before this one.
⇥ TABEvery recipe line must start with a real Tab character. Spaces won't work.
@Makes Make run the line without printing it first, so the output stays tidy.

The real file

Your Makefile, line by line

Save this as ~/docker-compose-stacks/Makefile, next to your stack folders. I ran make check with it against your repo, and all 7 stacks passed with no duplicate IPs.

Makefilerecipe lines start with a Tab
STACKS := traefik bind core immich-app arr monitoring portainer
A variable listing your stack folders in start order. Traefik comes first because the other stacks route through it. To add a new stack, add its folder name here.
s ?= $(STACKS)
?= sets s to all stacks unless you give it a value yourself. make up s=arr starts only arr. $(STACKS) is how you read a variable.
.PHONY: help network up down pull ps logs check
Tells Make these are command names, not files. Without this line, a file called up in the folder would make Make skip the rule.
help:
	@echo "make up | down | pull | ps | check | logs s=arr"
The first rule in the file is the default, so plain make prints this reminder.
network:
	@docker network inspect trfk >/dev/null 2>&1 || ./network/create-trfk.sh
	@docker network inspect direct-ip-macvlan >/dev/null 2>&1 || ./network/create-macvlan.sh
"Does the network exist? If not (||), run my script." Running it again is safe because it never creates a network twice.
up: network
	@for d in $(s); do echo "▶ starting $$d"; (cd $$d && docker compose up -d) || exit 1; done
Runs the network rule first, then goes into each folder and starts it. || exit 1 stops at the first stack that fails. $$d is a shell variable. Make uses $ for its own variables, so a shell $ has to be written twice.
down:
	@for d in $$(echo $(s) | tr " " "\n" | tac); do echo "■ stopping $$d"; (cd $$d && docker compose down); done
Stops the stacks in reverse order (tac flips the list), so Traefik stops last. down removes containers but keeps your data and volumes.
pull:
	@for d in $(s); do echo "↓ pulling $$d"; (cd $$d && docker compose pull) || exit 1; done
Downloads newer images without restarting anything. Run make up afterwards to switch to them.
ps:
	@docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
A neat table of what's running.
logs:
	@cd $(s) && docker compose logs -f --tail=50
Follows one stack's logs: make logs s=immich-app. Press Ctrl+C to exit.
check:
	@for d in $(s); do (cd $$d && docker compose config -q) && echo "ok   $$d" || exit 1; done
	@grep -hE "^[A-Z_]+_IP=" */.env | cut -d= -f2 | sort | uniq -d | grep . && echo "DUPLICATE IP above!" && exit 1 || echo "ok   no duplicate IPs"
Line 1 checks every compose file for typos and missing variables without starting anything. Line 2 collects every …_IP= from all your .env files and fails if two stacks use the same address. This is the protection your IPs were missing.
Gotchas

Four things that trip up everyone

Tabs, not spaces

If an editor turns the Tab into spaces, Make fails with this message:

Makefile:9: *** missing separator.  Stop.

In vim, :set noexpandtab before editing.

Every line is a new shell

A cd on one recipe line is forgotten on the next line. That's why the rules above put cd and the command on the same line.

$ vs $$

$(s) is Make's variable. $$d becomes $d for the shell. Forget the double $ and the value comes out empty.

Preview before running

make -n up prints every command it would run without running any of them. Use it whenever you're unsure.

Cheat sheet

What you'll type day to day

CommandWhat it does
makeShows the list of commands.
make checkValidates every stack and looks for duplicate IPs. Run it after editing any file.
make upCreates any missing networks, then starts every stack in order.
make up s=arrStarts or updates just the arr stack.
make up s="core arr"Several stacks. Put quotes around a list.
make pull && make upUpdates images, then restarts containers whose image changed.
make logs s=immich-appFollows Immich's logs.
make downStops everything in reverse order. Your data stays.
make -n upDry run: prints the commands without running them.
Getting started

Your first five minutes

  1. Create ~/docker-compose-stacks/Makefile with the contents above, or ask Claude to write it for you.
  2. cd ~/docker-compose-stacks. Make always reads the Makefile in the folder you're in.
  3. Run make to see the help line.
  4. Run make check. You should see ok for all 7 stacks.
  5. Run make -n up to preview, then make up for real, once Docker is running and Apache has freed ports 80 and 443.
